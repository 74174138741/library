# Linux 文件

Linux 里几乎所有能碰的东西都是文件：普通文件、目录、磁盘、管道、套接字，连进程信息也在 `/proc` 里以文件的形式露出来。命令和程序最终都是在对**路径 + 权限 + 文件描述符**动手。

---

## 1. 权限：谁能对这个文件做什么

三类身份 × 三种动作：

```
-rwxr-xr-x
│└┬┘└┬┘└┬┘
│ │  │  └ 其他人 (others)
│ │  └──── 所属组 (group)
│ └─────── 所有者 (owner)
└───────── 类型：- 文件  d 目录  l 链接
```

`r` 读 / `w` 写 / `x` 执行（目录上的 `x` 表示能进入）。数字写法：`r=4, w=2, x=1`，所以 `755` = 所有者 `rwx`、组和其他人 `r-x`。

```bash
chmod 755 mydir
ls -l                  # 第一列就是权限
```

**所有者**是创建者，或后来被 `chown` 改过的那个用户。一个用户可以同时属于多个组。

**root 不受这套三位权限限制。** 内核先看你是不是 root，是就放行，所以权限显示 `---` 时 root 仍能读。`sudo` = 临时用 root（或指定用户）的身份跑一条命令。

## 2. 目录与文件：日常命令

`ls` 颜色大致是：蓝=目录，绿=可执行，白=普通文件，红=压缩包。

```bash
ls -l                  # 权限、所有者、大小、时间
ls -a                  # 含隐藏文件（. 开头）
pwd                    # 当前目录
cd /path               # 进去
mkdir -p a/b/c         # 递归建目录
rmdir 空目录
rm -r 目录             # 递归删；rm -rf 强制且不询问
cp -r 源 目标
mv 源 目标             # 移动或改名
head -n 5 file.txt     # 前几行
tail -n 20 file.txt    # 后几行，看日志用这个
echo "hello"           # 把字打到标准输出
```

`rm -rf /` 会抹掉能写的整个根。记住它危险，不要拿来当例句跑。

找东西：

```bash
find /path -type d -name "文件夹名"    # 现场扫磁盘，准但慢
locate 名字                            # 走数据库，快，新文件可能还没进库
which python3                          # 可执行文件在 PATH 里的哪一个
whereis python3                        # 二进制 / 手册页等位置
```

挂载是把一块**已有的文件系统**接到目录树上的某个空目录，让你用路径访问它。方向是「外部设备/分区 → 本机某个挂载点」，不是把本机映射到外面去。

```bash
mount /dev/sdb1 /mnt
```

## 3. 数据流：命令怎么串起来

每个命令默认有三根管子：0 标准输入、1 标准输出、2 标准错误。

```
命令A 的输出 ──► 命令B 的输入      管道 |
命令 的输出 ──► 文件（覆盖）        >
命令 的输出 ──► 文件（追加）        >>
文件 ──► 命令的输入                 <
```

```bash
ps -ef | grep ros
echo hello > a.txt          # 覆盖
echo world >> a.txt         # 追加
grep "hello" < input.txt
```

通配符在**进命令之前**由 shell 展开，不是命令自己认的：

```bash
ls *.txt          # 任意长度
ls file?.txt      # 一个字符
ls file[1-3].txt  # 1、2 或 3
```

`grep` 按行过滤文本，常接在管道后面。

## 4. 程序里怎么碰文件

两层接口，干的是同一件事：

| | C 库 `FILE*` | 系统调用 `int fd` |
|---|---|---|
| 打开 | `fopen` | `open` |
| 读写 | `fprintf` / `fgets` | `write` / `read` |
| 关 | `fclose`（会刷新缓冲） | `close` |
| 删 | `remove` | `unlink` |
| 权限 | 打不开时指定不了模式细节 | `open(..., 0644)` 可指定 |
| 缓冲 | 有用户态缓冲 | 无，直接进内核 |

小文本、格式化输出用 `FILE*`。要精确字节、和管道/socket 同一套接口，用 `fd`。

```c
int fd = open("a.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
write(fd, "hi\n", 3);
close(fd);
```

## 5. 文件描述符

进程眼里，打开的每个文件都是一个小整数。惯例：

```
0  stdin     键盘 / 管道的左端
1  stdout    屏幕 / 管道的右端
2  stderr    错误，默认也去屏幕
3+ 你 open / socket / pipe 得到的
```

所以「一切皆文件」在编程里的落地就是：**管道、普通文件、套接字都用 `read` / `write`。** 重定向 `>` 本质是让 shell 把 1 号描述符改接到文件上。

---

## 6. 文件锁

多进程同时写同一文件会互相踩。内核提供文件锁，但默认是**劝告锁（advisory）**：只有大家都先检查锁再写，锁才有用。有一个进程不理锁直接 `write`，内核不管。把它当约定，不要当铁门。
