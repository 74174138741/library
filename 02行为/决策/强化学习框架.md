# 强化学习框架：Stable-Baselines3

[Stable-Baselines3 文档](https://stable-baselines3.readthedocs.io/en/master/)

SB3 把「跟环境玩、把数据攒起来、拿数据改网络」收成一套现成算法。你几乎只写：环境 + 选哪个算法 + `learn()`。算法原理在 [强化学习](强化学习.md)，这里只讲这套代码怎么分层。

源码目录大致是：`common/`（共用件）+ `ppo/` `sac/` `dqn/` `a2c/`（各算法自己的那一层壳）。

---

## 1. 五层在干什么

草稿里的箭头建议改成这样看——**不是单向漏斗**，而是算法在中间当导演，其它层被它来回调用：

```
你          model.learn() / predict()
                │
        ┌───────▼────────┐
        │  Algorithm     │  PPO / SAC / DQN / A2C
        │  训练流程导演   │  collect → 塞 buffer → train
        └──┬─────┬────┬──┘
           │     │    │
     Policy│  Env│    │Buffer
     神经网络    世界  │经验池
     看 s 出 a   step │
           │     │    │
           └─────┴────┘
                 │
            Optimizer   没有独立 Trainer 类
            算 loss、反向传播、改 policy 的权重
            写在 Algorithm.train() 里
```

源码里对得上的名字：

| 你记的层 | SB3 里实际是 | 干嘛 |
|---|---|---|
| Algorithm | `PPO` `SAC` `DQN` `A2C`，基类 `BaseAlgorithm` | 控制训练流程 |
| Policy | `ActorCriticPolicy` / `DQNPolicy` / `SACPolicy` | 神经网络：观测 → 动作（和价值） |
| Env | Gymnasium 环境 + `Monitor` + `VecEnv` | 世界：`reset` / `step` |
| Rollout Buffer | 在线：`RolloutBuffer`；离线：`ReplayBuffer` | 存交互数据 |
| Trainer | **没有单独类**，是 `algorithm.train()` + `torch.optim` | 算 loss、反向传播、更新 policy |

---

## 2. 算法层

管流程，不管「这个卷积长什么样」。`learn(total_timesteps)` 里转圈：

1. 用当前 policy 跟 env 玩一段时间（rollout）
2. 把 `(s, a, r, s', done, …)` 丢进 buffer
3. 调 `train()`：从 buffer 取数、算这个算法自己的 loss、更新网络
4. 重复，直到步数够

常见选择：

| 算法 | 动作 | 策略类型 | 什么时候用 |
|---|---|---|---|
| **PPO** | 离散 / 连续 | 在线 | 默认首选，稳 |
| **A2C** | 离散 / 连续 | 在线 | PPO 的瘦弱亲戚，更简单也更抖 |
| **SAC** | 连续 | 离线 | 机械臂、力矩这类连续控制 |
| **DQN** | 离散 | 离线 | 格子、按键、开关 |

在线（PPO/A2C）：用完这批轨迹就更新，buffer 是短命的 rollout。  
离线（SAC/DQN）：乱逛的经验和要学的目标可以不是同一套策略，buffer 是长期回放池。

你几乎只碰三个方法：`learn`、`predict`、`save` / `load`。

---

## 3. 策略层（神经网络）

Policy 是「眼睛 + 手」：输入观测，输出动作分布（PPO/SAC/A2C 还有一个价值头）。

默认字符串就能用：

- `"MlpPolicy"`：观测是向量（关节角、速度）
- `"CnnPolicy"`：观测是图像
- `"MultiInputPolicy"`：观测是 dict（图 + 向量拼在一起）

自定义两件事最常见：

- **改深浅**：`policy_kwargs=dict(net_arch=dict(pi=[64, 64], vf=[64, 64]))`
- **自己写特征提取器**：继承 `BaseFeaturesExtractor`，改输入通道、接自己的编码器，再交给 SB3 的动作头

算法问 policy 要动作时走 `predict`；训练时走 `evaluate_actions` / `forward`，好算 $\log\pi$ 和 $V$。

---

## 4. 环境层

环境就是马尔可夫那一套的代码化：`reset` 给初始 $s$，`step(a)` 返回 $s', r, \text{terminated}, \text{truncated}, \text{info}$。

SB3 不会直接抱着你的裸 env。`learn()` 前会包两层：

1. **`Monitor`**：记每局总分、长度，方便看曲线
2. **`VecEnv`**（`DummyVecEnv` 或 `SubprocVecEnv`）：一次跑 `n` 个环境，观测和动作都带 batch 维

所以你在 callback 里不要 `env.mu = ...` 直取属性，环境可能被包了好几层。改参数用 `env_method("set_mu", value)`。

环境要做的只有：定义观测/动作空间，写清奖励和结束条件。算法不关心你是 CartPole 还是真机器人，只认这份接口。

---

## 5. Buffer 层

存「刚才发生了什么」，给 `train()` 吃。

- **PPO / A2C**：`RolloutBuffer`。采满 `n_steps × n_envs` 就拿去更新，用完基本丢掉（在线）。
- **DQN / SAC**：`ReplayBuffer`。容量可以很大，随机抽 batch（离线、经验回放）。

字段无非是观测、动作、奖励、下一观测、结束标志；PPO 还会存 log 概率、价值、优势 $A_t$。你一般不用手写 buffer，换算法就换池子类型。

---

## 6. 优化（所谓 Trainer）

没有名叫 Trainer 的模块。`PPO.train()` / `DQN.train()` 里：

1. 从 buffer 取样
2. 用这个算法的公式算 loss（PPO 的 clip、DQN 的 TD、SAC 的 Q+熵）
3. `loss.backward()`，`optimizer.step()` 改 **policy 的权重**

优化器（默认 Adam）挂在 policy 上，导演仍是算法。

---

## 7. 一轮训练在干什么

以 PPO 为例：

```
reset 环境
        │
        ▼
policy.predict(obs)  ──► 动作
        │
        ▼
env.step(action)     ──► 下一观测、奖励、是否结束
        │
        ▼
写入 RolloutBuffer
        │
   步数未满 ──► 继续玩
        │
        ▼
算优势 A_t，train()：clip loss → 反向传播 → 更新 policy
        │
        ▼
清空（或覆盖）这批 rollout，再玩下一批
```

你写的 `model.learn(10000)` 就是把上面这件事重复到 10000 个 env.step。

---

## 8. 简单例子

CartPole：小车左右推，让杆别倒。观测 4 维向量，动作左/右两个键 → `MlpPolicy` + PPO。

```python
import gymnasium as gym
from stable_baselines3 import PPO

env = gym.make("CartPole-v1")

model = PPO(
    "MlpPolicy",
    env,
    verbose=1,
    learning_rate=3e-4,
    n_steps=2048,
)

model.learn(total_timesteps=20_000)
model.save("ppo_cartpole")

# 看它玩几步
obs, _ = env.reset()
for _ in range(200):
    action, _ = model.predict(obs, deterministic=True)
    obs, reward, terminated, truncated, _ = env.step(action)
    if terminated or truncated:
        obs, _ = env.reset()

env.close()
```

五层在这段代码里的对应：

| 代码 | 层 |
|---|---|
| `gym.make(...)` | Env |
| `"MlpPolicy"` | Policy（默认两层 MLP） |
| `PPO(...)` | Algorithm |
| `learn()` 内部 | Buffer 收集 + `train()` 优化 |
| `predict()` | 只用 Policy，不再更新 |

换连续控制，把 `PPO` 换成 `SAC`，环境换成 `Pendulum-v1` 即可；离散按键用 `DQN` 也行。环境接口不变，变的是导演和池子。

最小自定义环境：实现 `reset` / `step`，声明 `observation_space` 和 `action_space`，然后仍然 `PPO("MlpPolicy", env)`。算法层以下你都不用动。
